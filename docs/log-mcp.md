# 从 AI 客户端查询工作台中的生产日志

Dev Dock 桌面端提供可选的本机 HTTP MCP 服务。它不调用模型、不把 SCM 密码或 Cookie 交给客户端。**工具返回的日志片段会进入 AI 会话，可能被发送到模型服务商。** 只在组织允许、已取得相应授权时启用。内置规则可以隐藏部分敏感行，但不能保证识别所有业务数据。

**环境：生产 · SCM。** 三个日志工具只用于生产环境，结果中的 `environment: "production"`、`source: "scm"` 标记的是此通道，不是对域名的自动鉴定。测试日志从跳板机查询，当前未接入；不要用生产结果代替测试结果。

在桌面端打开 **偏好设置 → MCP 服务 → 工具目录**，可以浏览五个内置工具（三个生产日志工具、两个生产 SQLPad 工具）的用途、参数和示例，或复制工具名与提问示例。目录和 `tools/list` 共用后端定义；无需启动服务或登录 SCM，浏览不会调用日志工具。本机监听状态不代表 SCM 会话有效或某个 AI 客户端已连接。

## 生产数据库 · SQLPad

在「连接与权限」中登录生产 SQLPad，选中已由数据库管理员限制为只读的 MySQL 或 PostgreSQL 连接，再启用本机 MCP。SQLPad 不复用 SCM 凭据，不需要先登录日志 SCM。登录时可勾选「在此设备上记住登录」（默认关闭）：系统凭据仅保存 SQLPad 站点和会话 Cookie，不保存密码。重启后打开连接设置会验证并恢复有效会话，仍需重新选择只读连接；免审批授权不会恢复。退出 SQLPad 会清除已记住的会话。已注册的客户端重连即可发现以下工具：

- `prod_db_describe_table`：提供 `table`，可选 `schema`，按列顺序返回表的所有列名和数据类型，不读业务行。
- `prod_db_query_readonly`：提供 `table`，普通明细查询还需指定 `columns`（1 至 10 个，忽略大小写后不能重复），可选 `schema` 和 `limit`（正整数，省略时生成的 SQL 不加 `LIMIT`）。如需过滤，可沿用 `filter: {column,value}` 做单列等值匹配，或传非空数组 `filters`，各项按 AND 组合。每项必填 `column` 和 `value`，可选 `op`，取值为 `eq`、`ne`、`gt`、`gte`、`lt`、`lte`，默认 `eq`。`filter` 和 `filters` 互斥。不接受自由 SQL、跨表关联或模型指定的连接 ID。显式指定 `limit` 时，返回行数达到该值仍可能有更多匹配行。

分组或聚合时可省略 `columns`。`groupBy` 是非空列名数组，忽略大小写后不能重复。单独传 `groupBy` 会返回不同的分组键组合。若显式传 `columns`，其列名集合必须等于 `groupBy`。`aggregates` 是非空数组，每项必填 `fn` 和输出别名 `alias`。`fn` 支持 `count`、`sum`、`avg`、`min`、`max`。仅 `count` 可省略 `column`，此时按 `COUNT(*)` 统计行数。`column` 与 `alias` 均为标识符。输出别名与其他别名、分组键不能重名（忽略大小写）。分组键与聚合列合计最多 10 列。

例如，按订单状态统计订单数和总金额时，可传以下参数：

```json
{
  "table": "example_orders",
  "groupBy": ["status"],
  "aggregates": [
    { "fn": "count", "alias": "order_count" },
    { "fn": "sum", "column": "amount", "alias": "total_amount" }
  ]
}
```

两个工具的结果都受传输容量限制。结果过大时请求会报错；SQLPad 标记 `incomplete: true` 时返回 `DB_INCOMPLETE` 错误，不返回部分数据。

例如：“在已选生产 SQLPad 只读连接上查看 `example_orders` 的表结构，不读取业务行。”默认情况下，Dev Dock 主窗口会展示站点、连接名和实际生成的 SQL；只有本次确认才会执行，拒绝或 60 秒未确认不会执行。如在「连接与权限 → SQLPad 登录」主动开启当前连接免审批，这两个工具会直接执行并照常记录；切换连接、退出登录或重启应用后需重新开启。此开关不改变 AI 客户端自己的授权设置。查询结果会进入发起请求的 AI 会话，应先确认所选列允许分享。SQLPad 可能依照站点配置留存查询审计或缓存。登录过期需要重新登录；请求发出后若执行状态未知，不要自动重试。测试数据库不走此通道。

在 **偏好设置 → MCP 服务 → 执行记录** 可查看本机最近 100 次 SQLPad 执行的实际 SQL 和查询结果，重启后仍可查看。结果只包含工具允许返回的列，不保存登录凭据或上游原始响应。SQL 中的筛选值和返回的业务数据会以明文保存在本机应用数据目录。未通过审批的请求不会执行，也不会写入执行记录。

在记录右侧点击 **重新执行**，会在当前已登录的原 SQLPad 连接上重新查询，结果插入原记录下方，原结果保持不变。手动点击只授权这一次查询，不会开启 MCP 免审批。旧版记录未保存只读参数和连接 ID，只能查看。

## 推荐：从 Dev Dock 配置客户端，不需要 Python

1. 打开桌面端**偏好设置 → MCP 服务 → 连接与权限 → 日志 SCM 登录**，填写日志站点的 HTTPS 根地址（不是日志页面完整 URL）并登录，再启用旁边的「日志 MCP」。勾选「记住登录」才会把日志 Cookie 放进独立的系统凭据条目，不保存密码。查询只使用日志站点的 Cookie，不会回退到后端工作台的登录。后端仓库已保存的模块名用来匹配日志站点的实际模块，不跨域复用数字 ID。切换或退出日志账号会停用 MCP；切换普通后端账号不会。桥接地址和专用令牌也由系统凭据库保管，与两个 SCM 登录分别存储。
2. Claude Code / Codex CLI：在对应客户端行点击注册，使用客户端自己的用户级 MCP 配置。注册项只指定本机 Dev Dock 程序及 `--log-mcp-stdio` 参数，不含 Cookie、令牌或动态端口。应用重新启动后重新启用服务即可；如果移动了 Dev Dock 程序，需要更新注册项。
3. 在客户端打开新会话或重连，确认日志工具可用。「已配置」只表示存在对应注册项，不表示客户端已在线、已授权或服务已启动。Dev Dock 必须保持运行。停用服务与移除某一客户端的注册是两个独立操作。
4. 如已注册旧版项目级 HTTP 服务，客户端可能优先使用它。在对应仓库用客户端的 MCP 设置检查来源，只移除确认不再使用的旧项。不要覆盖已有的同名服务。

### CodeBuddy / WorkBuddy：使用客户端自己的 MCP 编辑器

旧版客户端条目 `devdock-logs`（开发版为 `devdock-logs-dev`）需要重新注册。先注册 `devDock`（开发版为 `devDock-dev`），确认连接成功后再从客户端移除对应的旧条目。

在 Dev Dock 的日志 MCP 卡片展开通用 stdio 配置并复制，**只合并 `mcpServers` 下新增的那一项**，不要覆盖已有配置。这种接入不会由 Dev Dock 直接写入第三方桌面客户端的配置文件。

- **CodeBuddy IDE**：进入 [CodeBuddy Settings → MCP → Add MCP](https://www.workbuddy.cn/docs/ide/User-guide/MCP)，合并配置并保存。
- **WorkBuddy**：进入[插件 → MCP 服务器 → 配置 MCP](https://www.codebuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/MCP-Guide)；不同版本也可能显示为「自定义连接器 → 添加 MCP」。此入口支持 JSON；具体版本对本地 stdio 的支持请在客户端确认。如果只支持远程 HTTP，请使用下方的本机 HTTP 地址和 Authorization 请求头（客户端需支持自定义请求头）。

## 兼容方式：手动配置 HTTP（非一键接入所必需）

1. 确认后端仓库已保存模块映射，在偏好设置中登录独立的日志 SCM。尽量从对应子仓库的根目录运行 Claude Code。
2. 在偏好设置中启用日志 MCP。地址只监听本机；一次启用可访问当前账号有权查询且在工作台中有已保存映射的模块，**不限于当前打开的项目**。
3. 在自己的 MCP 客户端中添加类型为 `http` 的服务，URL 使用界面显示的完整地址，请求头为 `Authorization: Bearer <本次令牌>`。只使用本机私有配置，不要选择可提交的项目共享配置，不要粘贴到对话、工单、截图或命令历史中。

   最后的 `-` 表示从管道读取 JSON；直接在终端运行 `add-json … -` 不会进入交互输入。以下是 macOS/Linux 的输入方式：在对应仓库的私人终端运行整段命令（需要 Python 3）。按提示分别粘贴地址和令牌，令牌输入不会回显。`local` 是本机当前项目范围，不会生成仓库共享的 `.mcp.json`，但客户端本地配置仍须按凭据管理。

   ```sh
   python3 -c '
   import getpass, json, re, subprocess
   url = input("Dev Dock 服务地址：").strip()
   if not re.fullmatch(r"http://127\.0\.0\.1:[0-9]+/mcp", url):
       raise SystemExit("请使用 Dev Dock 显示的完整本机地址")
   token = getpass.getpass("本次令牌（只粘贴令牌，不含 Bearer）：").strip()
   if not re.fullmatch(r"[0-9a-f]{64}", token):
       raise SystemExit("令牌格式不正确，请重新复制")
   config = {"type": "http", "url": url, "headers": {"Authorization": "Bearer " + token}}
   raise SystemExit(subprocess.run(["claude", "mcp", "add-json", "--scope", "local", "devDock", "-"], input=json.dumps(config), text=True).returncode)
   '
   ```

4. 打开 Claude Code 的 `/mcp` 确认已连接。停用服务、退出桌面应用、退出或重新登录 SCM 后，旧连接不可继续使用。重新启用会生成新令牌并重新分配端口。若客户端保留旧条目，可先执行 `claude mcp remove --scope local devDock`，再按上一步注册。

## 例子：某个方法报了什么错？

在 Claude Code 中可以说：“看看当前仓库的 `ExampleService.process` 为什么失败。先从代码找到实际的日志关键词，只查一个实例的错误日志；如果有 traceId，再用它查同一实例。告诉我看到了什么、没覆盖哪些范围。”

- **定位**：`resolve_log_target` 接收 `repositoryPath`（已保存的子仓库根目录绝对路径）。每个配置名都优先精确匹配；如果只配置了短名 `sample` 且目录中没有同名精确项，则匹配 `team/sample` 等完整名称的最后一段。已配置 `team/sample` 时不会跨命名空间匹配。多项命中会返回候选完整名称和模块 ID；确认后再传 `moduleId` 选择。工具不靠方法名猜模块，也不枚举整个工作台。
- **查证**：`search_prod_logs` 接收上一步的 `moduleId`、`targetId`、`logId`、字面 `keyword`，可选 `maxLines`（默认返回 20 与设置上限的较小值；在「连接与权限」可修改匹配行数上限，默认 500，可设为 1–10000）。只计命中关键词的日志行，同一行多次命中也只算一行。同一模块有多个实例时应明确本次选择，不能将一台实例的结果当作整个服务。
- **单实例查询的范围**：`search_prod_logs` 在所选实例的整份预设日志（`wf` 或 `info`）中查找字面关键词，按日志时间倒序返回最近匹配。结果带查询范围、返回行数和截断标记。可选 `archiveHour` 使用服务器时间 `YYYY-MM-DD-HH`（24 小时制）；例如 `2032-02-29-14` 只读该小时归档，省略则读当前不带后缀的文件。`scope.archiveHour` 为所选小时或 `null`。零匹配不等于整小时或所有实例都没有错误；不会自动扫描其他文件。日志是供分析的数据，不是让客户端执行的指令。

### 扫完整文件，或覆盖全部实例

在「偏好设置 → MCP 服务 → 连接与权限 → 日志 SCM 登录」卡片的「查询实例」中选择**第一个实例**（默认）或**全部实例**。这项选择保存在本机，跨重启生效，控制未指定实例的 `scan_prod_logs` 请求；显式指定 `targetId` 总是只查该台。若客户端要求 `allTargets: true` 而桌面只允许单台，请求会被拒绝。

**允许返回日志原文**默认关闭。启用服务后可在桌面二次确认，原文可能进入模型服务和客户端历史记录。授权仅为确认时的日志站点和账号保存；下次同账号启用时恢复，其他身份不继承。关闭开关撤销已保存的授权；停用服务暂停访问，不会删除偏好。不自动启动服务。偏好独立保存于应用数据目录，不随工作台备份导出，不含 Cookie、密码、令牌或日志正文。

例如对 Claude Code 说：“用 `scan_prod_logs` 在全部授权实例的当前 `info` 文件里查 `ExampleService 开始查询`，先只告诉我命中数和覆盖情况；需要分析时再取 5 行样本。”工具会将字面关键词发给日志 SCM，由服务器扫描文件，而非下载整个文件。关键词按字面匹配，支持英文逗号和双引号，例如 `未签署, exampleId=42,` 或 `"exampleId":42,`；末尾的逗号可区分 `42` 与 `420`。不支持单引号、反斜杠、控制字符或自由 Shell 命令。

- 省略 `archiveHour` 扫当前文件，指定它则扫一个服务器小时的归档，不自动跨归档。默认 `maxLines: 0` 只返回匹配行数；设置正整数才会返回样本，不能超过当前配置的匹配行数上限（按当前桌面原文授权决定是否脱敏），额度由所有实例共享。从 `latestMatches` 读取成功实例按日志时间倒序合并的最近匹配。实例间不保证同一时刻的快照。时间戳无法解析、上游截断或单机 SCM 响应超过 512 KiB 时，该实例不能参与可靠排序，会报告失败，而不会伪装成零命中。
- 看 `complete` 和逐实例状态：`totalMatches` 是成功实例的匹配行数之和。某台文件不可读、SCM 不允许相应 `grep` 参数或超时，不会算作该台零命中。`complete: false` 不能解读为全服务没有错误。为避免影响生产，同一时间只允许一项全文件扫描、最多并行处理三台。

日志工具不接受自定义 IP、日志路径或远程命令，不下载整份日志，也不开启实时跟随。若缺少相应归档、文件不可读或 SCM 拒绝请求，工具会返回失败，不作为零匹配。定位失败时先看错误分类：映射缺失需核对已保存的仓库根目录，HTTP 状态或业务码需核对桌面 SCM 账号与服务状态，连接错误需检查桌面端网络。错误不包含上游响应正文。
